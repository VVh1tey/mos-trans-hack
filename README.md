# Прогноз задержек городского транспорта

Дашборд воспроизводит историческую телеметрию, показывает GPS-позиции машин и
прогнозирует задержку на целевой остановке за 10–15 минут до планового прибытия.
Backend отправляет записи датасета по TCP в формате NDTP и вызывает CatBoost
для подходящих остановок. Приёмник проверяет пакеты и хранит позиции для карты.

**[Гайд по дашборду со скриншотами](docs/dashboard-guide.md)** ·
[Модель](runs/20260927T210831784612Z-robust-final/catboost.cbm) ·

[Архитектура](docs/architecture.drawio)

## Запуск для жюри

Нужны Git и Docker с Compose v2, запущенный Docker Engine / Docker Desktop
в режиме Linux containers. Python и Node на хосте для запуска не нужны.
Первая сборка скачивает образы и зависимости; подложка карты требует интернета.
Все команды выполняются **из корня репозитория**, рядом с `compose.yaml`.

### 1. Подготовить файлы

Распакуйте данные (dataset.zip) в `dataset/`, без дополнительного уровня
вложенности вроде `dataset/dataset/test/`. Минимальная структура для полного показа:

```text
mos-trans-hack/
├── compose.yaml
├── dataset/                         ← добавить из архива организаторов
│   ├── test/
│   │   ├── traffic.csv              ← обязательная телеметрия
│   │   └── schedule.csv             ← обязательное расписание с фактами
│   └── labels/
│       └── labels_test.csv          ← контрольные точки и расчёт MAE
├── runs/                            ← выбранный run включён в Git
│   ├── selection.json
│   └── 20260927T210831784612Z-robust-final/
│       ├── catboost.cbm
│       ├── manifest.json
│       ├── metrics.json
│       ├── oof.csv
│       ├── catboost_robust.py
│       └── catboost_context.py
└── data/                            ← справочники и геометрия из репозитория
```

`dataset/` не включён в Git. Для текущего Compose файл
`dataset/labels/labels_test.csv` должен существовать **до запуска**: он монтируется
отдельно как файл. Сохраняйте исходные заголовки и содержимое CSV.
`train/`, `validate/` и `labels_train.csv` нужны для обучения, но не для показа.

Модель готова: **обучать и выбирать её заново не нужно**.
Если исходники передаются отдельно от артефактов, скопируйте **всю папку run**
по указанному пути и `runs/selection.json`, а не один `catboost.cbm` в корень.
Имя каталога должно совпадать с `run_id` в `selection.json`.

### 3. Показать прогноз

1. Откройте «Сеть» и нажмите **«Запустить»** в блоке исторических данных.
2. Для быстрого перехода к прогнозам выберите **×3600**, затем верните **×60**.
   В начале файла подходящих остановок нет: первое окно указано под таймлайном.
   На ×1 ожидание идёт в реальном времени датасета.
3. Дождитесь роста счётчика «Прогнозов модели» и нажмите на машину на карте.
   Справа появятся прогноз, время целевой остановки, run модели и состояние GPS.
4. «Пауза» останавливает виртуальное время. «Продолжить» сохраняет позицию,
   «С начала» очищает текущие результаты и возвращает воспроизведение к началу.

Для прогноза нужны расписание, подходящий пакет и остановка в интервале
**(T + 10 минут, T + 15 минут]**. Для одной целевой остановки повторный потоковый
прогноз делается не чаще раза в 120 секунд времени датасета.

### Признаки и API

12 исходных признаков: `cur_dev_s`, `abs_dev`, `hour`, `hour_sin`, `hour_cos`,
`horizon`, `target_lon`, `target_lat`, `planned_gap`, `segment_m`, `stops_ahead`,
`adjusted_stops_ahead`; для каждого добавлен индикатор пропуска.
GPS-признаки в эту модель не входят, ID машины и остановки не используются как признаки.

`POST /api/predict` требует `sample_id`. Пропуски допускаются, но пустой вход
даёт общий обученный прогноз, а не информированную оценку рейса.
Пример с дополнительным контекстом (иллюстративные значения):

```json
{
  "sample_id": "bus-123-now", "cur_dev_s": 120,
  "T": "2026-01-06T12:00:00+03:00",
  "target_time_begin": "2026-01-06T12:12:00+03:00",
  "target_lon": 37.62, "target_lat": 55.75,
  "planned_gap": 180, "segment_m": 800,
  "stops_ahead": 4, "adjusted_stops_ahead": 5
}
```

`planned_gap` — секунды между предыдущим и целевым плановым прибытием,
`segment_m` — метры по прямой между этими остановками. `stops_ahead` — число
прибытий в `(T, target_time_begin]`, `adjusted_stops_ahead` — в
`(T-cur_dev_s, target_time_begin]`. Время передаётся в согласованной временной зоне.
ML-сервис сам не загружает расписание по ID: эти признаки рассчитывает клиент.
Текущий replay передаёт время, горизонт и текущее отклонение, но не все признаки
планового контекста; **75,31 с не является заявленным качеством текущего replay**.

## Телеметрия и границы реализации

Рабочий путь: `test CSV → backend replay → TCP NDTP → ingest → HTTP snapshot → карта`.
Отдельно replay вызывает ML по событиям датасета и подходящему расписанию.
Это исторические данные через настоящий TCP-приёмник, а не подключение к городскому парку.

Приёмник собирает фрагментированные кадры, проверяет CRC, отбрасывает дубли
и запоздавшие пакеты. При повреждении полного кадра повторно ищет сигнатуру,
сохраняя следующие корректные кадры. Недостоверный GPS и скачки с расчётной
скоростью выше 160 км/ч не перемещают маркер. Последняя позиция сохраняется
до 120 секунд; свежесть replay считается по виртуальному времени.
Карта использует интерполяцию Web Mercator и не анимирует разрывы более 90 секунд.
Сброс защищён от пакетов старых соединений. После ошибки TCP отправитель
переподключается и повторяет пакет один раз; при повторном отказе ставит replay на паузу.
[Алгоритм координат и маппинга](backend/README.md).

Позиции и результаты replay хранятся в памяти и теряются при перезапуске
соответствующих сервисов. Гарантии доставки каждого пакета и архивирования нет.
Каталог линий, маршрутные показатели, инциденты, история и What-if используют
демонстрационные данные; связь GPS-машин с линиями каталога не установлена.
Вероятность задержки robust-модель не рассчитывает.

**Где смотреть алерты:** в «Сети» цвет маркера и риск в карточке ТС зависят
от настоящего прогноза replay (или наблюдаемого отклонения, когда прогноза нет).
Раздел «Инциденты» показывает демонстрационные карточки, а не журнал алертов
по принятому потоку. Отдельный сохраняемый журнал реальных алертов и их доставка
не реализованы. Если жюри требует именно такой журнал, этот пункт функциональности
остаётся ограничением текущего решения.

Предоставленный NDTP-эмулятор необязателен для основного показа. Для отдельного
запуска положите `ndtp-telemetry-emulator.tar` в `dataset/`:

```sh
docker load -i dataset/ndtp-telemetry-emulator.tar
docker compose --profile emulator up -d emulator
```

API эмулятора: http://localhost:18081; адрес назначения внутри Docker — `ingest:9201`.
Его устройства не сопоставлены с расписанием и сами по себе не порождают прогнозы
replay. Запуск исторического воспроизведения отключает генерацию эмулятора.

## Обновление и диагностика

После изменения исходников нужна пересборка:

```sh
docker compose up -d --build --wait
docker compose logs --tail 100 backend ml ingest
```

Обновите браузер через Ctrl+F5. После пересоздания backend запустите replay заново.
При временном обрыве приёмника нажмите «Продолжить» после восстановления сервиса.

| Симптом | Что проверить |
| --- | --- |
| ML не запускается | `runs/selection.json`, папку run, `manifest.json`, `catboost.cbm`; логи ml |
| «Данные недоступны» | Три CSV на нужных путях; `labels_test.csv` должен быть файлом, не каталогом |
| Прогнозов 0 | Replay запущен, первое окно достигнуто, нет ошибки воспроизведения |
| У выбранного ТС нет прогноза | Есть расписание и остановка через 10–15 минут |
| `Broken pipe` / нет приёмника | `docker compose ps`, логи ingest; затем «Продолжить» |
| Карта без подложки | Доступ к `tile.openstreetmap.org`; линии и маркеры работают отдельно |
| Занят порт | Переопределите соответствующий порт в `.env` |

Остановка: `docker compose down`. Volumes Prometheus и Grafana сохраняются.
Удаление volumes для обычного перезапуска не требуется.

## Обучение и проверка артефакта

Для обучения нужен полный архив с `train/`, `test/`, `validate/` и `labels/`.
Команда создаёт **новый** run, не перезаписывая поставляемую модель:

```sh
docker compose -f compose.train.yaml run --build --rm trainer python -m experiments.catboost_robust
docker compose -f compose.train.yaml run --rm -e AUDIT_RUN_DIR=/runs/20260927T210831784612Z-robust-final trainer python -m experiments.test_robust
```

Выбор другого совместимого run и его загрузка:

```sh
docker compose -f compose.train.yaml run --rm trainer python choose.py <run_id>
docker compose up -d --force-recreate ml
```

Тесты backend в Linux / Python 3.12: `python -m unittest discover -s backend -p 'test_*.py'`.
Frontend: `cd frontend`, `npm ci`, `npm run build`.

### Производительность

Измерение 28.09.2026 МСК: Docker / WSL2, AMD Ryzen 7 7800X3D,
8 доступных логических CPU, Python 3.12.14. По 10 прогревочных и 100 измеряемых
последовательных запросов на endpoint, один клиент, вход `cur_dev_s=120`.
Измерено с клиента внутри Docker-сети, без браузера и внешнего nginx.

| Путь | p50 | p95 | Последовательных запросов/с | Ошибки |
| --- | ---: | ---: | ---: | ---: |
| HTTP ML `/predict` | 4,64 мс | 5,32 мс | 216,8 | 0 / 100 |
| HTTP backend `/api/predict` → ML | 5,62 мс | 6,29 мс | 178,4 | 0 / 100 |

Декодер обработал 20 000 NDTP-кадров в памяти за 0,456 с: около
43 884 кадров/с, без ошибок CRC. Это **только декодирование**, без TCP,
GPS-фильтра, хранения и карты. HTTP-результаты получены с неполными признаками;
это локальный замер прогретого сервиса, не предел нагрузки и не задержка
всего пути «GPS → экран».

[Полные результаты и параметры](docs/performance.json).


### Реализованные дополнительные возможности

- Replay с виртуальным временем, паузой, сбросом и скоростями ×1–×3600.
- GPS-фильтрация, сохранение последней достоверной позиции, отображение свежести.
- Восстановление после повреждения NDTP-кадра и повтор подключения при ошибке TCP.
- Плавное движение в Web Mercator с учётом пропусков GPS и reduced motion.
- Модель с поддержкой пропущенных признаков и проверкой с исключением машин.
- Отображение факта и ошибки после наступления события, диагностический MAE.
- Prometheus и Grafana для мониторинга сервисов.
- Поиск маршрутов, избранное, пороги/цвета риска и экспорт демонстрационного журнала.
- What-if выпуска машин — **демонстрационная формула**, не обученная модель.

Map matching на дорожную сеть, ансамбль CatBoost + нейросеть, ONNX/TensorRT,
постоянное хранение телеметрии и журнал реальных алертов не реализованы.
