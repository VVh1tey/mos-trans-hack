# Backend: телеметрия и отображение на карте

Запуск, данные и модель описаны в [корневом README](../README.md).
HTTP API: [Swagger UI](http://localhost:18000/docs) и [OpenAPI](openapi.json).
Код: [PyDoc](../docs/pydoc/index.html), после запуска — http://localhost:18080/code-docs/.

## Как координата попадает на карту

1. `replay.py` читает события `traffic.csv` по времени и сопоставляет `unit_id`
   терминала с `tr_id` машины. Каждую запись отправляет по TCP как NDTP Nav00.
   Это сопоставление идентификаторов, а не поиск дороги или маршрута.
2. `ndtp.py` собирает кадр из TCP-фрагментов, проверяет заголовок и CRC.
   Долгота и широта передаются целыми числами: делим на `10⁷`, применяем знаки
   из флагов. Результат — **`[longitude, latitude]` в градусах**, именно в этом порядке.
   Проверяются пределы ±180° / ±90°, флаг GPS, спутники и PDOP.
3. `ingest.accept_event()` отбрасывает поздние события и дубли с тем же временем
   и packet ID. При плохом GPS сохраняет последнюю принятую координату.
   Для новой позиции рассчитывает расстояние по гаверсинусу и скорость
   `distance_km / delta_seconds × 3600`. Выше `GPS_MAX_SPEED_KMH` (160 по умолчанию)
   — статус `suspect`, маркер остаётся на прежнем месте. Отвергнутый скачок
   не становится базовой точкой следующего сравнения.
4. `/telemetry` отдаёт снимок, время пакета и время последней достоверной позиции.
   `simulation.py` дополняет его расписанием и прогнозом. В replay возраст считается
   от виртуального `currentTime`: после 90 секунд пакет устарел, после 120 секунд
   без достоверной позиции маркер скрывается. У живого приёмника свежесть пакета
   считается по времени получения (10 секунд), хранение позиции —
   `GPS_RETAIN_SECONDS` (120 по умолчанию).
5. Frontend передаёт координату в `MapLibre.Marker.setLngLat()`.
   MapLibre проецирует её в Web Mercator. `frontend/src/telemetryMotion.ts`
   интерполирует между принятыми точками в плоскости этой проекции:
   `y = ln(tan(π/4 + latitude/2))`, затем выполняет обратное преобразование.
   Через границу ±180° выбирается короткий путь; широта для отрисовки ограничена
   ±85,05113°. Некорректные координаты не передаются карте.

Длительность перехода учитывает скорость replay и ограничена 900 мс.
При паузе, устаревшем пакете, разрыве свыше 90 секунд или настройке
«уменьшить движение» интерполяция отключается. Движение за пределы
последней принятой координаты не прогнозируется.

**Привязки GPS к ближайшей дороге или линии маршрута (map matching) нет.**
Геометрия линий загружается отдельно; машина рисуется по принятому GPS.
Поэтому близость маркера к линии на карте не подтверждает принадлежность маршруту.

## Устойчивость потока

Сброс replay меняет поколение приёмника: старые TCP-соединения не могут вернуть
очищенные позиции. Повтор той же координаты с тем же временем не обновляет
возраст позиции. При ошибке отправки replay переподключается и повторяет тот же
пакет один раз; повторный отказ приостанавливает воспроизведение с сообщением.
TCP send не является подтверждением обработки, полной гарантии доставки нет.

`test_ndtp.py`, `test_ingest.py`, `test_replay_predictions.py` проверяют разбиение
кадров, восстановление после повреждения, GPS-фильтрацию, сброс через реальные
TCP/HTTP-сокеты, переподключение и вызовы модели.
