# Быстрые эксперименты с признаками

## Обнаружена зависимость train и контрольных данных

Аудит после двух score 1.00000 выявил утечку через синтетические копии:
все 26 машин, оставшихся после фильтра по `tr_id` (3293 строки), повторяют
полные последовательности координат остановок 13 реальных машин из test.
В каждой паре всё плановое расписание сдвинуто на одну постоянную величину,
а среднее абсолютное различие фактических задержек составляет 14–18 секунд.
22 синтетические машины соответствуют 11 машинам validate.
Пересечений ID машин/примеров после фильтра нет, но независимость источников
не обеспечена. Предыдущий CatBoost с тем же фильтром также затронут.

Официальные score 1.00000 и приведённые ниже MAE не доказывают обобщение
на независимые поездки. При исключении всех семейств test/validate train пуст.
Для независимой локальной оценки нужно заново разбить исходные данные по
семействам «реальная машина и её синтетические копии» и переобучить модели.
Аудит: `python scripts/audit_model_leakage.py`, результат `outputs/leakage_audit.json`.
Сам код признаков не читает фактические прибытия; финальные сабмиты совпали
с сохранёнными в проверенных запусках.

## Запуск

Из корня проекта (готовый Docker-образ trainer уже должен существовать):

```powershell
docker compose -f compose.train.yaml run --rm -v "${PWD}/ml/experiments:/app/experiments:ro" trainer python -m experiments.catboost_context
docker compose -f compose.train.yaml run --rm -v "${PWD}/ml/experiments:/app/experiments:ro" trainer python -m experiments.catboost_telemetry
```

Или один раз собрать образ `docker compose -f compose.train.yaml build trainer`,
затем запускать эти команды без `-v`.

Обе команды обучают модель, оценивают исходный test и сразу создают
`outputs/submission_context.csv` / `outputs/submission_telemetry.csv`.
Модель, метрики, важность признаков, копия submission и исходников сохраняются
в отдельном каталоге `runs/`. `CB_ITERATIONS` можно передать через `-e` (по умолчанию 700).
Модули также поддерживают обычный `TRAIN_MODULE=experiments.catboost_context`
или `experiments.catboost_telemetry` для `train.py`.

Используется та же очистка train по машинам test/validate, что в лучшем прежнем
эксперименте. Новых разбиений нет. CatBoost обучается с MAE на поправку к `cur_dev_s`.
Контекст: время суток, горизонт, координаты целевой остановки, длина предыдущего
отрезка, интервалы расписания, число остановок впереди с учётом текущей задержки.
Телеметрия: последние достоверные GPS, скорость, давность, расстояние до цели,
движение и доля стоянок за 1/5/15 минут, положение относительно плановых остановок.
Телеметрия отбирается строго по `event_time <= T`; фактические прибытия расписания,
классы и целевые задержки не входят в признаки. Статические внешние справочники
не потребовались: координаты остановок уже есть в расписании.

Локальный test, 353 точки: прежний CatBoost — 88.11 с; context — 59.14 с;
telemetry — 54.08 с. Первым стоит отправить **submission_telemetry.csv**.
Это примерно 38.6% улучшения локального MAE, не подтверждённый рост score платформы.
Финальные запуски: `20260927T204822377080Z-context` и
`20260927T204824991102Z-telemetry`. Ранние отладочные запуски этих модулей
недействительны из-за исправленной ошибки единиц времени pandas.
Проверено: замена будущих GPS и фактических прибытий не меняет признаки.
Test использован для сравнения вариантов;
независимая проверка — скрытый validate на платформе.

Существующая активная модель не переключается. Эти два эксперимента предназначены
для офлайн-сабмита: для онлайн-сервиса нужен сбор тех же признаков из потока,
`choose.py` их пока не поддерживает.
