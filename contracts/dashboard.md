# Dashboard HTTP API v1

Все URL относительно origin фронтенда. Vite и nginx проксируют `/api/` на backend.
Типы ответов: `frontend/src/types.ts`. Клиент: `frontend/src/api.ts`.

| Метод | URL | Назначение |
| --- | --- | --- |
| GET | `/api/dashboard?period=60` | Согласованный снимок сети |
| GET | `/api/dashboard/routes/{id}?direction=0&period=60` | Срез одного маршрута |
| GET | `/api/dashboard/settings` | Пороги и цвета риска |
| POST | `/api/dashboard/settings` | Валидация и сохранение настроек |
| POST | `/api/dashboard/routes/{id}/scenario` | Сравнение What-if с базовым планом |
| GET | `/api/dashboard/simulation` | Конфигурационный статус эмулятора и последняя принятая телеметрия |
| POST | `/api/dashboard/simulation` | `{"action":"start"}` / `{"action":"stop"}` |

`period`: 30, 60, 180 минут. `direction`: 0 или 1. Для кольцевого маршрута
с одним направлением используется 0. Неизвестный маршрут — 404, некорректные
параметры — 400, тело ошибки `{ "error": "описание" }`.

Для симуляции тип ответа — `SimulationStatus`. `running: null` означает неизвестное состояние (эмулятор недоступен),
`available` и `ingestAvailable` описывают доступность двух сервисов независимо. `telemetry: null` означает отсутствие связи
с приёмником; пустой `vehicles` — снимок без принятых Nav00. Время `eventTime`/`receivedAt` задано Unix-секундами,
`coordinates` — `[longitude, latitude]` в градусах. `stale` наступает через 10 секунд без нового пакета устройства.
Счётчики накоплены с запуска ingest. Ошибка управления возвращает 503; неподдерживаемое действие — 400.
Симуляция не меняет `mode: demo` существующего маршрутного снимка. [Подробности](../docs/ndtp-simulation.md).

## Снимок

`mode` (`demo` / `live`), `generatedAt` (время данных), `servedAt` (время HTTP-ответа),
`notice`, `settings`, `summary`, `routes`, `incidents`, `history`, `historyEvents`.
Время — ISO 8601 UTC; интерфейс отображает московское время. Координаты — `[lon, lat]`.
Величина отклонения — целое число секунд; положительное значение означает задержку.

Для маршрута передаются идентификатор справочника, номер, название, тип транспорта,
геометрия выбранного направления, остановки, ТС и агрегаты. ID ТС в демо искусственные
и не связаны с `tr_id` модели. `stops` — ближайшие остановки к десяти равноудалённым
по длине точкам линии, без утверждения официального порядка или расписания.

`incidents[].id` — идентификатор ТС, `alertId` — стабильный ключ `(ТС, остановка)`.
`historyEvents` — отдельная демонстрационная история прогнозов. Отметка «просмотрено»
хранится только в браузере; это не серверный жизненный цикл инцидента.

## Правила метрик

- ТС на линии: количество ТС текущего среза. План: демо-факт + 2 ТС на маршрут.
- Высокий риск: количество ТС с `delaySeconds >= highDelaySeconds`.
- Средний риск: `mediumDelaySeconds <= delaySeconds < highDelaySeconds`.
- Низкий риск: задержка ниже среднего порога.
- Инциденты: ТС среднего и высокого риска; статус маршрута — максимальный риск его ТС.
- Средний прогноз: среднее задержек всех ТС среза, округлённое до секунды.
- Свежесть: доля ТС с `ageSeconds <= staleAfterSeconds`. Снимок демо неподвижен;
  возраст пакетов увеличивается, а HTTP-опрос не делает телеметрию свежей.
- `probability` иллюстрирует вероятность задержки более 120 секунд; это не выход
  обученного классификатора. Смена порогов цвета не меняет смысл этой вероятности.
- Фильтры ограничивают список/карту; верхние KPI относятся ко всему выбранному уровню.

## Настройки

```json
{"mediumDelaySeconds":120,"highDelaySeconds":420,"staleAfterSeconds":90,
 "colors":{"low":"#24855b","medium":"#bd7608","high":"#b52238"}}
```

Целые пороги `0 < medium < high <= 3600`; свежесть 15–3600 секунд. Цвета — три
`#RRGGBB`. Настройки общие для вкладок, хранятся в памяти процесса до перезапуска.

## What-if

```json
{"extraVehicles":1,"horizonMinutes":60,"direction":0,
 "startStopId":"ID из routes[].stops","startTime":"01:15"}
```

ТС: 1–5, горизонт: 30/60/120 минут, время: ЧЧ:ММ МСК. Ответ: `mode`, `model`,
`routeId`, исходные `parameters`, `notice`, массив сравнений `metrics`
(`label`, `unit`, `baseline`, `scenario`) и ряд `series` (`minute`, `baseline`, `scenario`).

`illustrative-headway-v1` — демонстрационная формула чувствительности к числу ТС,
положению остановки, горизонту и времени суток. Она не обращается к ML и не выпускает
ТС на линию. Обученная what-if-модель впоследствии заменяет только провайдер результата.

## Подключение online

Заменить `backend/dashboard.py` провайдером Redis/PostgreSQL с теми же полями.
Выставить `mode=live`, обеспечить реальные `observedAt`, `generatedAt`, связь
`tr_id → routeId`, порядок остановок и происхождение вероятностей. Фронтенд опрашивает
snapshot каждые 15 секунд и при возвращении во вкладку; при ошибке сохраняет последний
снимок и показывает отсутствие связи. SSE можно добавить в слой получения данных.
Существующий `POST /api/predict` сохранён и по-прежнему вызывает ML-сервис.
